# PyTorch-VAE プロジェクト: AFHQ データセットでの学習と環境構築の軌跡

## 1. 当初の目的

`VanillaVAE`モデルを使い、`AFHQ`データセット（犬と猫のみ）で学習を行う。

## 2. データセットの準備 (`dataset.py`の修正)

- **課題:** プロジェクト標準のデータローダーが`CelebA`データセットに固定されていた。
- **対応:**
  1.  `AFHQ`データセットを読み込むため、`torchvision.datasets.ImageFolder`をベースにした`AFHQDataset`クラスを`dataset.py`に新設。
  2.  `VAEDataset`モジュールの`setup`メソッドを修正し、ハードコードされていた`MyCelebA`の代わりに`AFHQDataset`を呼び出すように変更。
  3.  犬と猫のみを学習対象とするため、`unzip`後に`train`と`val`の両ディレクトリで`mv Data/afhq/train/wild Data/afhq/train/wild.bak`コマンドを実行し、`wild`クラスを対象外にした。

## 3. `VanillaVAE`での動作確認とデバッグ

- **課題:** 本格的な学習の前に、素早く動作確認を行いたい。
- **対応:** `fast_dev_run: True`を設定したデモ用の設定ファイル(`tmp_vae.yaml`)を作成。
- **発生したエラーと解決策:**
  1.  **`ModuleNotFoundError: No module named 'yaml'`**
      - **原因:** `PyYAML`ライブラリの不足。
      - **解決:** `pip install PyYAML`を実行。
  2.  **`FileNotFoundError: Found no valid file for the classes dog`**
      - **原因:** データセットの zip ファイルが正しく展開されていなかった。
      - **解決:** `unzip Data/afhq.zip -d Data/`で正しく展開し直した。
  3.  **`AttributeError: 'DummyLogger' object has no attribute 'log_dir'`**
      - **原因:** `fast_dev_run`モードではログを保存しない`DummyLogger`が使われるが、コードがログディレクトリの存在を前提としていた。
      - **解決:** `experiment.py`を修正。`isinstance`での型チェックが`ImportError`を招いたため、最終的に`if hasattr(self.logger, 'log_dir'):`というコードで、ロガーに`log_dir`属性がある場合のみ画像サンプリングを行うように変更した。
- **結果:** 上記の修正を経て、`VanillaVAE`でのデモ実行（1 バッチの学習・検証）に成功。

## 4. `ConditionalVAE`での条件付き学習

- **課題:** `VanillaVAE`ではラベル情報を利用した「条件付き学習」ができないことが判明。
- **対応:** モデルを`ConditionalVAE (CVAE)`に切り替えることを決定。
- **設定ファイルの作成:**
  1.  `cvae.yaml`をテンプレートとして、AFHQ データセット用の新しい設定ファイルを作成。
  2.  後々の管理のしやすさを考慮し、`configs/afhq_experiments/`という新しいディレクトリを作成。
  3.  `num_classes: 2`, `gpus: [0]`, `max_epochs: 30`に設定を修正した`cvae_afhq.yaml`を上記ディレクトリに保存。
- **発生したエラーと解決策:**
  1.  **`RuntimeError: mat1 and mat2 shapes cannot be multiplied`**
      - **原因:** モデル（CVAE）が期待するラベルの形式（One-Hot ベクトル）と、データローダーが渡す形式（クラスインデックス）が異なっていた。
      - **解決:** `models/cvae.py`の`forward`および`sample`メソッドを修正。クラス番号を受け取った後、`F.one_hot()`を使ってモデル内部で One-Hot ベクトルに変換する処理を追加した。
  2.  **`RuntimeError: CUDA error: CUBLAS_STATUS_EXECUTION_FAILED`**
      - **原因:** `cuDNN`を無効化しても、今度は`cuBLAS`でエラーが発生。PyTorch、CUDA、GPU ドライバ間のより根深い非互換性の問題であると判断。
      - **解決:** 個別のライブラリの修正ではなく、開発環境そのものを見直す方針に決定。

## 5. 次のステップ

- **結論:** 環境起因のトラブルを根本的に解決するため、動作検証済みの環境をパッケージ化した**Docker**を導入する。
