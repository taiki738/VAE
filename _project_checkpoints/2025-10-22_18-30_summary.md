# PyTorch-VAE CVAE モデル デバッグの要約

## 1. 当初の目的

`ConditionalVAE`モデルを、`AFHQ`データセットの「犬」と「猫」クラスのみを使用して条件付きで学習させる。

## 2. 課題と解決のステップ

### STEP 1: 環境起因のエラーと Docker の導入

- **課題:** ローカル環境で`CUBLAS_STATUS_EXECUTION_FAILED`という CUDA エラーが発生。PyTorch、CUDA、ドライバ間のバージョン不整合が疑われた。
- **解決策:** 実行環境の再現性を高めるため、Docker を導入して開発環境をコンテナ化する方針を決定。
  1.  PyTorch 公式の CUDA 付きイメージ (`pytorch/pytorch:2.1.0-cuda11.8-cudnn8-runtime`) をベースにした`Dockerfile`を作成。
  2.  不要なファイルがイメージに含まれないよう、`.dockerignore`ファイルを作成。
  3.  `sudo`権限で Docker イメージをビルドし、コンテナを起動。

### STEP 2: モデルの入力チャンネル数の不整合

- **課題:** Docker コンテナ内で学習を実行したところ、ローカル環境と同じ`CUBLAS`エラーが再発。これにより、問題が環境ではなくコードにあることが確定。エンコーダー部分 (`F.conv2d`) でエラーが発生していた。
- **原因:** `cvae.py`の`forward`メソッドが、画像(3ch)とラベル情報を連結してエンコーダーに渡していたが、エンコーダー側の入力チャンネル数の定義が`画像のチャンネル数 + 1`となっており、実際のデータ(`画像のチャンネル数 + クラス数`)と一致していなかった。また、ラベル情報を結合する実装が非常に複雑で、エラーの温床となっていた。
- **解決策:**
  1.  `__init__`メソッドを修正し、エンコーダーの入力チャンネル数を`in_channels + num_classes`に変更。
  2.  `forward`メソッドを修正し、One-Hot エンコードしたラベルを画像と同じサイズに拡大してチャンネル方向に連結する、よりシンプルで標準的な実装に変更。

### STEP 3: テンソルのデバイス不整合 (CPU/GPU)

- **課題:** STEP 2 の修正後、エラー箇所がエンコーダーからデコーダー (`F.conv_transpose2d`) に移動。
- **原因:** `forward`メソッド内で、GPU 上にある潜在変数`z`と、CPU 上に残っていたラベルの One-Hot ベクトル`y_one_hot`を結合しようとしていたため。
- **解決策:** `torch.cat`で結合する直前に、`y_one_hot.to(z.device)`を追記し、ラベル情報も GPU に移動させるように修正。

### STEP 4: データセットのラベル範囲外エラー

- **課題:** `RuntimeError: CUDA error: device-side assert triggered` という、より具体的なエラーに変化。`CUDA_LAUNCH_BLOCKING=1`を付けてデバッグ実行した結果、`F.one_hot(y, self.num_classes)`の行でエラーが発生していることが判明。これは、`num_classes=2`に対して範囲外（`0`, `1`以外）のラベルが渡されていることを示す。
- **原因:** `ls`コマンドで確認したところ、検証用データセットのディレクトリ (`Data/afhq/val/`) 内に、除外したはずの`wild.bak`フォルダが残っていた。`ImageFolder`はこれを`cat`, `dog`に続く 3 つ目のクラス（ラベル`2`）として認識していた。
- **解決策:** `Data/afhq/val/wild.bak` ディレクトリを完全に削除。

### STEP 5: 未使用パラメータによる分散学習エラー

- **課題:** 学習が 1%進んだ直後、`parameters that were not used in producing loss` というエラーで停止。
- **原因:** STEP 2 の修正で不要になった`self.embed_class`と`self.embed_data`レイヤーの定義が`__init__`メソッド内に残っており、「モデルの一部だが、損失計算に使われていないパラメータ」として PyTorch Lightning の分散学習機能に検知されたため。
- **解決策:** `__init__`メソッドから、不要になった 2 つのレイヤーの定義を削除。

## 3. 現在の状況と次のステップ

全てのデバッグが完了し、モデルは学習可能な状態になりました。

次回は、コンテナ内で以下のコマンドを実行することで、中断した箇所から学習を再開できます。

```bash
python run.py -c configs/afhq_experiments/cvae_afhq.yaml
```
