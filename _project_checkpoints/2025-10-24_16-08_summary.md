# PyTorch-VAE プロジェクト: CVAE AFHQ サンプリングと追加学習の軌跡 (2025-10-24)

## 1. 当初の目的

学習済み`ConditionalVAE`モデルを用いて`AFHQ`データセットの条件付きサンプリングを実行し、その後モデルの追加学習を行う。

## 2. 条件付きサンプリング機能の実装

### 2.1. `sample.py`の新規作成

既存の`run.py`ではサンプリングのみの実行が困難であったため、以下の機能を備えた`sample.py`を新規作成した。

*   学習済みチェックポイントからのモデルロード
*   指定されたクラスIDとサンプル数に基づく条件付きサンプリング
*   生成された画像のファイル保存

### 2.2. `sample.py`のデバッグと修正

1.  **`TypeError: ConditionalVAE.sample() missing 1 required positional argument: 'current_device'`**
    *   **原因:** `sample.py`内で`model.sample()`を呼び出す際に、引数名が`device`となっていたが、`models/cvae.py`の`ConditionalVAE.sample`メソッドは`current_device`という引数名を要求していたため。
    *   **解決:** `sample.py`内の`model.sample()`呼び出しを`current_device=device`に修正した。

2.  **画像ファイル名の改善**
    *   **目的:** 今後の比較のため、保存される画像ファイル名にモデル名を含める。
    *   **解決:** `sample.py`内のファイル名生成ロジックを修正し、`samples_{model_name}_class_{class_id}_n_{num_samples}.png`の形式で保存するように変更した。

## 3. Docker環境での実行とトラブルシューティング

### 3.1. `docker run`コマンドの修正

*   **問題:** `sudo docker run`で`command not found`エラーが発生。
*   **原因:** `sudo`を付けた際に`root`ユーザーの`PATH`に`docker`コマンドのパスが含まれていなかったため。現在のユーザーは`docker`コマンドを実行可能であった。
*   **解決:** `sudo`を外し、`docker run -it --rm --gpus all -v $(pwd):/workspace pytorch-vae`で実行するように修正した。

### 3.2. Dockerイメージの再ビルド

*   **問題:** `Unable to find image 'pytorch-vae-dev:latest' locally`エラーが発生。
*   **原因:** `pytorch-vae-dev`というイメージがローカルに見つからなかったため。ユーザーの記憶違いで、正しいイメージ名は`pytorch-vae`であった。
*   **解決:** 正しいイメージ名`pytorch-vae`で`docker run`を試す。もしイメージが存在しない場合は`docker build -t pytorch-vae .`で再ビルドする。

### 3.3. コンテナ内の作業ディレクトリの理解

*   **問題:** `python sample.py`実行時に`No such file or directory`エラーが発生。
*   **原因:** `Dockerfile`の`WORKDIR /app`によりコンテナのデフォルト作業ディレクトリは`/app`だが、`sample.py`は`-v $(pwd):/workspace`でマウントされた`/workspace`に存在していたため。
*   **解決:** コンテナ内で`cd /workspace`を実行し、作業ディレクトリを移動してから`python sample.py`を実行するようにした。
*   **概念の整理:** `Dockerfile`によるイメージ内のファイル配置（`/app`）と、`docker run -v`によるホストとのファイル共有（`/workspace`）の違いを説明し、ユーザーの理解を深めた。

## 4. 学習済みモデルの追加学習

### 4.1. 追加学習の実行

*   **方法:** `run.py`の`--resume`オプションを使用し、`logs/ConditionalVAE/version_9/checkpoints/last.ckpt`から学習を再開した。
*   **コマンド:** `python run.py -c configs/afhq_experiments/cvae_afhq.yaml -r 'logs/ConditionalVAE/version_9/checkpoints/last.ckpt'`

### 4.2. 学習がすぐに終了する問題

*   **問題:** 追加学習コマンド実行後、学習ループに入らずすぐに終了した。
*   **原因:** `configs/afhq_experiments/cvae_afhq.yaml`の`trainer_params`セクションで`max_epochs: 30`と設定されており、モデルが既に30エポック学習済みであったため、すぐに終了条件を満たしてしまった。
*   **解決:** ユーザーが`max_epochs`を100に変更し、学習を再開した。

## 5. 学習ログの確認とTensorBoard

*   **ログの保存場所:** `logs/ConditionalVAE/version_X/`ディレクトリ内に、`checkpoints/`、`Samples/`、`Reconstructions/`、`events.out.tfevents...`などが保存されることを説明。
*   **TensorBoardでの可視化:** ホストマシンで`tensorboard --logdir logs`コマンドを実行することで、学習の進捗をリアルタイムで確認できることを案内。
*   **主要なロスの説明:**
    *   **KLD (Kullback-Leibler Divergence):** 潜在空間の分布が事前分布にどれだけ近いかを示す指標。潜在空間の秩序を保ち、生成能力を向上させる役割。
    *   **Reconstruction Loss (再構築ロス):** 入力画像と再構築された画像との間の差を示す指標。モデルが画像をどれだけ正確に再現できているかを表す。
